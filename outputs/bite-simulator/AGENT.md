# 开发代理约束

## 不可破坏的物理约束

- 不得为了“不卡”而放宽 `80 µm` 穿透硬门、`8192` 子步上限或事务回滚语义。
- 不得用速度限幅、按齿数缩冲量、PID、经验阻尼或位置投影伪装修复。
- 接触尝试失败时必须恢复 Rapier 世界、关节、碰撞组、固定步长、接触账本、owner/handoff 和材料状态；只允许保留明确标记的拒绝态诊断峰值。
- 材料模式缺少已验证能力时应报 `material-model` 并保留上一安全帧，不能静默切换成刚体冲量。
- `rigid-solver`、`material-model`、`internal` 三种失败域必须保持可区分。
- 参数武器允许叉接触启动持久接触簇时，必须保留 `paramWeaponEnabled` 保护；CAD 武器尚无对应 MLCP 外轮廓见证，不能被错误屏蔽。
- 武器质量是公开输入，惯量由当前有效几何自动推导。旧 API 的 `weaponInertia` 不得覆盖自动值。

## 文件与发布

- 正式开发目录是 `outputs/bite-simulator`；`outputs` 与 `work` 当前映射到 E 盘。
- 已冻结的 `bite-simulator-v1.0` 是发布基线，不得原地覆盖。后续发布应复制到新版本目录。
- 用户提供的 DXF/DWG 不得移动或删除；需要打包、测试或迁移时只能复制。
- 编辑文本文件使用补丁方式，保留用户已有改动；不要用重置、检出或递归删除清理工作区。
- 临时浏览器 profile 只能放在 `work`，清理前先确认没有进程占用且解析后的路径确实位于 `work`。
- 修改 `app.js` 后必须同步提升 `index.html` 中脚本与样式缓存版本；README/HANDOFF 说明也要同步。

## 最低验证要求

- 每次改动至少运行语法检查和 `run-final-static-qa.js`。
- UI/输入改动运行 `run-ui-final-qa.js`、`run-param-runtime-qa.js`。
- 质量/几何/惯量改动运行 `run-automatic-weapon-inertia-qa.js`。
- 失败域、回滚或异常路径改动运行 `run-p0-failure-domain-qa.js`。
- 接触求解改动必须覆盖参数/CAD 武器与参数/CAD 叉、低传动比、多初始角、多齿，并断言：无非预期停止、接受态穿透不超过 `80 µm`、越门尝试已回滚、接触最终可分离、能量账闭合、互补与摩擦锥残差合格。
- 不能只凭画面或一条成功轨迹声称“符合现实”；应记录模型边界、失败域和收敛证据。

## 当前最高优先事项

1. CAD 武器的持久外轮廓接触见证与联立求解。
2. 有历史状态、连续 TOI 和余步重演的材料剐蹭/删料模型。
3. Worker 化预计算与不改变轨迹的性能优化。
4. 更完整的底盘、轮地和整机姿态自由度。
